*file-tools.txt*  File operations and tree

Requirements: Neovim 0.11+. No external program dependencies.
Optional dependency: theme-tools.nvim for shared semantic colors.
Optional dependency: nvim-web-devicons for file type icons and colors.
Optional dependency: image-tools.nvim for image and PDF previews.
No mappings, netrw replacement, cwd changes or LSP configuration are automatic.

COMMAND                                                        *:FileTools*

    :FileTools [toggle|open] [directory]
    :FileTools close
    :FileTools find [directory]
    :FileTools refresh
    :FileTools create path       Trailing / creates a directory.
    :FileTools rename path       Move the current file buffer to path.

The argument after the action is one literal path, including spaces. Do not add
shell quotes. Commands report errors through vim.notify. Lua operations return
an event or nil, error. Use the tree's d mapping for confirmed deletion.

Toggle keeps focus and cursor position in the current window when opening the
tree. With tree.follow enabled (the default), opening also expands and selects
the current file, using its parent as root if outside the tree root. Open and
find focus the tree. Use <C-w>h to enter a tree on the left.

TREE                                                     *file-tools-tree*

    <CR>, l, double-click   Open a file or toggle a directory.
    h                       Collapse directory or select parent.
    <Tab>                   Open a single floating preview; focus stays in Files.
    P                       Toggle preview that follows the selection.
    <Esc>                   Close preview.
    s / S / t               Vertical split / horizontal split / tab.
    a / r / d               Create / move or rename / delete permanently.
    y / x / p               Copy / cut / paste (never overwrite).
    Y                       Copy absolute path to unnamed and + registers.
    .                       Toggle dotfiles.
    R                       Refresh.
    -                       Use parent directory as tree root.
    C                       Use selected directory as tree root.
    f                       Reveal the editor's file.
    q                       Close tree.
    ?                       Show keys.
    /                       Native Neovim filename search.

Each tab has its own tree. Only expanded directories are scanned; directory
symlinks are not traversed. Tree roots do not change cwd. Files open in the
editing window, preserving the tree. Watchers refresh visible directories, with
a limit of 64 watchers per tree. R refreshes when watchers are unavailable.
An entry limit bounds rendering; narrow the root if it is reached. Unreadable
directories are displayed as errors. Closing the tree releases its resources.

FLOATING PREVIEW                                       *file-tools-preview*

Press <Tab> to preview the selected file in a nonfocusable float beside Files.
Repeated <Tab> keeps it open; moving to another file closes this single preview.
P toggles following preview, which updates as the selection moves. P on a single
preview enables following; <Tab> returns to single preview. <Esc>, leaving Files
(including opening a file) or closing the tree releases the window and renderer.
Selecting a directory closes any open preview. <Tab> and P do nothing on
directories, including the root row.
Terminal resizing adjusts the float and reuses uploaded image pixels.

Text previews read at most 256 KiB, display up to 500 lines and truncate lines
to 2000 bytes. Other binary files show a placeholder.
Previews use the file on disk and do not modify files or editor buffers.
Text highlighting uses installed Tree-sitter parsers and runtime queries,
falling back to Vim syntax when unavailable. The preview sets 'filetype' without
running FileType handlers or attaching language servers. LSP semantic tokens
and editor-specific decorations are not copied from editing buffers.

Images and PDF page one use the optional image-tools.nvim embedded render API.
Configure it in your plugin manager; lazy loading is supported. Rendering needs
a Kitty graphics compatible terminal with 'termguicolors'. Image conversion uses
image-tools' configured tools: ImageMagick, with Ghostscript for PDFs. Errors or
missing dependencies appear in the preview instead of opening binary data.
PDF requests use fit_pixels=true and render_scale=2: vectors are rasterized to
the float's pixel box at 2x sampling, using terminal cell pixels or the cell_size
fallback. This avoids enlarging a low-resolution image of a small cropped PDF.
Targets use 64-pixel buckets within image-tools' pixel/dimension limits. Smaller
windows reuse pixels; larger windows upgrade detail. Image-tools must support
fit_pixels.
Adaptive PDF previews require pdfinfo (Poppler) for page dimensions/rotation.
Rapid selection changes discard pending work and reject stale draws/errors.

File/folder icons are enabled by default; use a Nerd Font in your terminal.
If nvim-web-devicons is available, file icons and colors come from its filename
and extension lookup, including user overrides. Otherwise a generic file icon
is used. Folder icons reflect open/closed state and use FileToolsDirectory.
Set tree.icons=false to hide icons and avoid loading the provider.

LUA API                                                   *file-tools-api*
>
    local files = require("file_tools")
    files.setup({})
    files.toggle({ root = "/project" })
    files.open({ root = "/project", reveal = "/project/main.lua", focus = false })
    files.find()
    files.close()
    local event, err = files.create("/project/main.lua")
    files.create("/project/assets", { directory = true })
    files.rename("/project/main.lua", "/project/app.lua")
    files.copy("/project/assets", "/project/assets-copy")
    files.delete("/project/assets-copy", { recursive = true })
<
toggle() opens without taking focus unless focus=true is passed. open() and
find() focus the tree unless focus=false is passed.

setup() is optional. It registers the command and configures defaults; UI modules
load only when used. No global key mappings are installed. Paths are normalized
to absolute paths, resolving parent symlinks while preserving leaf symlinks.
Parent directories must exist. Destinations must be absent, including conflicting
buffers. Directory self-moves and cross-device moves are refused. Symlink copies
retain the link; copying a directory stages content in a sibling temporary path.

Rename retains buffer identity, unsaved text and undo history without saving.
The next ordinary :write works. Buffers with matching BufWriteCmd handlers are
refused before moving. Dirty buffers briefly serialize their undo history in a
private temporary directory to preserve undo save points while clearing Vim's
renamed-file write guard; the temporary file is removed immediately.

Delete refuses dirty buffers. A nonempty directory requires recursive=true.
Tree deletion asks for confirmation with Cancel as the first choice. Deletion
is permanent; it is not a trash or undo service. Window layout is retained.

LSP                                                       *file-tools-lsp*

Merge files.capabilities() into the capabilities passed to each server BEFORE
starting it. setup() does not patch existing clients. Static and dynamic file
operation registrations select recipients by workspace, URI scheme, glob,
file/folder kind and case option. Rename considers both old and new paths.

Will-file requests finish before mutation. Timeout, error, stale text, unsupported
resource/annotated edits or multiple responses targeting the same document abort
the operation. Supported text edits preserve each client's encoding and remain
unsaved. Changed buffers are rechecked after requests. A failed filesystem
mutation restores applied text; undo history from the attempted edit may remain.
Recursive deletion can be partially completed on a filesystem failure. Operations
are not atomic transactions. Copy sends didCreate only.

After mutation, buffers synchronize and matching servers receive did-file
notifications. Rename detaches/reattaches open documents using public Neovim APIs
so servers receive didClose/didOpen under the correct URI.

OTHER FILE FRONTENDS                                   *file-tools-reconcile*
>
    files.reconcile({ kind = "Rename", path = old, to = new })
    files.reconcile({ kind = "Delete", path = deleted, directory = true })
    files.reconcile({ kind = "Create", path = created })
<
Call only after a completed external operation. reconcile returns true or
nil, error. It never mutates the filesystem and sends did-file notifications
only. Normal create/rename/delete/copy return an event or nil, error.
External deletion keeps dirty text as an unnamed buffer and records the old
name in b:file_tools_deleted_path. For deleted folders, supply directory=true
if the folder kind cannot be inferred from open descendants.

Successful changes emit User FileToolsChanged with ev.data containing kind
(Create/Rename/Delete), absolute path, optional to, directory, and external=true
for reconciled operations. Copy emits Create. Tree views subscribe to this event.

SHARED THEMES                                             *file-tools-theme*

When theme-tools.nvim is loaded, File-tools subscribes to its shared palette via
on_change("file-tools.tree", callback). It follows managed theme switches,
scheduled direct :colorscheme changes, transparency, palette overrides and
refresh_palette(). The tree retains its buffer, folds and cursor. The shared
subscription survives repeated theme-tools setup and supports later loading via
User ThemeToolsReady. No theme manager or colorscheme is initialized by File-tools.

Declare theme-tools.nvim as a plugin dependency to load its service first, or
keep your existing theme-tools setup. Without it, standard highlight links work
standalone. This is an optional dependency; file operations do not use it.

    FileToolsRoot             ui.accent (bold)
    FileToolsDirectory        palette.blue
    FileToolsFile             ui.fg
    FileToolsSymlink          palette.cyan
    FileToolsNormal           ui.fg / ui.bg (including transparent backgrounds)
    FileToolsCursorLine       ui.cursorline_bg
    FileToolsWinSeparator     ui.border / ui.bg
    FileToolsError, Warn       diagnostic.error / diagnostic.warn

Window-local winhighlight maps the tree's normal background, cursor line and
separator to these groups. Standard editor highlight groups remain unchanged.

CONFIGURATION                                           *file-tools-config*
>
    require("file_tools").setup({
      lsp = { enabled = true, timeout_ms = 1500 },
      tree = {
        width = 40, side = "left", show_hidden = false,
        follow = true, max_entries = 5000, icons = true,
      },
    })
<
tree.side is left or right. Use :checkhealth file_tools for diagnostics.
